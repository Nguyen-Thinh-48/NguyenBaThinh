## Why write it by hand

I spend most of my time putting models on accelerators. That job goes badly if you
treat the model as a file. When a network drops six points of accuracy after INT8
conversion, "the quantizer did it" is not a diagnosis.

So I rebuilt the stack from the bottom: a tokenizer, then positional encoding, then
attention, then a working GPT, then an INT8 quantizer for it — each in a notebook, each
with the intermediate tensors printed and checked. The corpus is Vietnamese text, which
made the character-level vocabulary interesting on its own: `à á ả ã ạ` are five
distinct characters, so `V` grows to **228** for 409,721 characters of text.

Everything is measured against a calibration point that costs nothing to compute: an
untrained model should sit at `ln(V) = 5.429`. If a freshly initialised network does not
report that loss, there is a bug, and no amount of training will fix it.

  ### The shape that never changes

  Every layer takes `[B, T, C]` and returns `[B, T, C]`. That is not an accident — the
  residual connection `x = x + f(x)` forces both sides to be the same size, and it is
  exactly that constraint that makes depth a free dial: any block plugs in after any
  other block.

  Multi-head attention **divides** the width rather than multiplying it. With `C=128`
  and four heads, each head works in 32 dimensions, so four independent views of the
  sequence cost the same as one wide one. `C % n_head == 0` is a hard requirement —
  `Block(128, 5)` silently discards three dimensions instead of raising.

  Writing out the parameter budget by hand — 29,184 for tokens, 32,768 for positions,
  197,888 per block, then the head — is the cheapest debugging tool in the project. If
  `sum(p.numel())` does not match the arithmetic, something is wired wrong.

## What the measurements said

Two knobs, both of which "obviously" help, measured against wall-clock:

| Change | Val loss | Time | Parameters |
| --- | --- | --- | --- |
| Context `T` = 64 | 1.421 | 257 s | 883,172 |
| Context `T` = 128 | **1.389** | 558 s | 883,172 |

Doubling the context cost **2.2× the training time** and bought 0.032 of loss — and not
one extra parameter, because the attention matrix is `[B, n_head, T, T]` and grows with
`T²` while the weights do not. That single table is the whole motivation for
flash-attention, sliding windows and linear attention, and it is more convincing having
watched the clock myself.

Going from 2 to 4 layers bought 0.041 of loss for 81% more parameters and 97% more time
— a better deal than the context increase, which is the sort of thing you only find out
by trying both.

## The bug worth keeping in the writeup

`max_len` was 256, but training ran at `T=128`. Generation, meanwhile, was allowed to run
out to 256 characters.

Rows 128–255 of the positional embedding table had therefore never received a single
gradient. They were still random initialisation. Generated text was fine for exactly 128
characters and then collapsed into noise — which looks like a sampling bug, or a
temperature problem, or a corpus problem, and is none of those.

It is a good bug because the failure is loud but the cause is silent: nothing in the
code is wrong, the table is simply larger than the training ever reached. Generate at the
context length you trained at.

## INT8, one rung at a time

The quantization notebook works up in eight steps, from affine `FP32 → INT8 → FP32`
round-tripping, through the arithmetic of scale and zero-point, to the parts that
actually bite in production:

- **Outliers.** A single extreme activation stretches the scale factor and crushes every
  ordinary value into a handful of levels. This is the entire reason methods like AWQ
  exist, and it is much clearer after watching one outlier destroy a tensor.
- **Clipping before quantizing**, and what accuracy that trades away.
- **Calibration** on data the range was not fitted to — the honest test, since a scale
  tuned on the calibration batch will always flatter itself.
- **Applying it to the GPT built earlier**, rather than to a toy tensor.
- **Memory on disk versus memory in RAM**, which are not the same number and disappoint
  people who expected a 4× saving everywhere.

## What is in the repository

Five notebooks — tokenizer and positional encoding, attention, the GPT, a BPE-level
variant, and the INT8 ladder — plus a written parameter reference (`THAM_SO_GPT.md`) that
explains every hyperparameter with the measured effect of changing it, and three
standalone HTML visualisers for stepping through the data flow.

It is a study project and it says so. The value is that the next time a model loses
accuracy on a Hailo or a TensorRT conversion, I know which layer to suspect.
